# SquareNet — sitio web

Sitio estático (HTML/CSS/JS vanilla, sin build step) para SquareNet Software, empresa ecuatoriana de software de nómina/RRHH. No hay `package.json`; se sirve directo (`python -m http.server` para probar local).

## Sistema de diseño

Todo el sitio usa `css/broadsheet.css` — un design system "editorial broadsheet":
- Fuente: Source Serif 4 (`--font-heading`, `--font-body`), pesos serios, sin sans-serif genérica.
- Acento principal teal (`--color-accent*`), secundario magenta (`--color-accent-2*`) — usar con moderación.
- Radios de borde **muy sharp** (`--radius-sm:1px`, `--radius-md:2px`, `--radius-lg:4px`) — nunca cards muy redondeadas.
- Tokens de espaciado `--space-1..8`, sombras `--shadow-sm/md/lg`.
- Componentes reutilizables ya existentes: `.tag`/`.tag-accent`, `.card`/`.card-title`/`.card-body`, `.kicker`+`h1` (patrón eyebrow+heading en cada página), `.btn-primary`/`.btn-secondary`, `.wrap` (max-width 1320px), `.hero`, `.modules-grid` (hover lift + gradient overlay), `.feature-carousel`.
- **Superficie oscura compartida**: `.band-dark` (degradado teal con toque magenta — la misma receta del carrusel del home) para bandas/tarjetas/ilustraciones oscuras; `.hero-art` (tarjeta 4:3 con grilla de puntos + SVG de línea) para el "hero" ilustrado de las páginas internas. Usarlos antes que inventar otro fondo oscuro: el usuario ya pidió consistencia de lenguaje visual entre páginas.
- **Arte de línea compartido `.la`** + `js/art.js`: contenedor `.la` con un SVG cuyas clases `.la-main/.la-soft/.la-acc/.la-dash/.la-glow/.la-chip/.la-txt` dan el estilo (blanco + acento cian). Los trazos con `data-draw` se dibujan solos (el JS mide `getTotalLength()`), `data-pop`/`data-fade` entran con escala/fundido, y todo arranca al entrar en pantalla (`.la-ready` → `.is-play`). Reglas aprendidas: nunca `data-pop` sobre un elemento con atributo `transform` (el CSS lo pisa — envolverlo en un `<g>`); los selectores de clase con ancestro NO aplican dentro de `<use>`; para un trazo con huecos usar segmentos separados, no `stroke-dasharray` (choca con el dibujado).
- Estilos específicos de cada página viven en un `<style>` inline en el `<head>` de esa página (no se tocan los estilos de otras páginas). Excepción: los componentes de artículo del blog (`.article*`, `.article-cover/.article-facts/.article-callout`, `.related*`) viven en `broadsheet.css` porque los usan los 7 posts.
- **Canales de soporte NO son públicos** (decisión del cliente, por riesgo de phishing/ransomware): no publicar `soporte@squarenet.com.ec` ni el WhatsApp de soporte (+593 98 220 4777) en ninguna página. El botón flotante de WhatsApp (`.whatsapp-float`) se quitó de las 26 páginas; su CSS sigue en `broadsheet.css` por si algún día hay un número de **ventas** para usarlo (con el glifo oficial de WhatsApp, no el ícono de teléfono). Canales públicos: PBX (02) 450-7012, celular 099 824 2295, info@ y ventas@.

Cada página nueva o rediseñada debe reusar estos tokens/componentes en vez de inventar un sistema paralelo.

- **`index.html` showcase del laptop** (`#pantallas`, entre el hero y el carrusel; el kicker y el tag "Fácil, ágil, dinámico" del hero se quitaron a pedido del cliente): un laptop en CSS puro (tapa con bisel, base con muesca, brillo teal y sombra; todo en `cqw` con `container-type:inline-size` para que escale) cuya pantalla 16:10 reproduce el video del recorrido por las pantallas reales del sistema. Debajo, el texto "Más de 40 pantallas en un solo sistema" (el 40 cuenta de 0 a 40; la cifra la afirma el cliente) y los íconos Roles de pago / Resúmenes de horario / Ausentismos / Personal / Contratos / "…y muchas más". Al entrar en pantalla la tapa se abre (`rotateX`, solo sin `prefers-reduced-motion`).
  - **Video**: el maestro es `squarenet-full-loop-v2.mp4` en la raíz (30 MB, 1920×1200 @60 fps, 142 s, sin audio, sin trackear: no commitearlo ni servirlo). La web usa `media/squarenet-loop.mp4` (1280×800 @60, ~7 MB), `media/squarenet-loop-sm.mp4` (960×600 @30, ~4 MB, para ≤700 px de ancho) y el póster `media/squarenet-loop-poster.jpg` (fotograma de 72.6 s: la pantalla de roles de pago). El video empalma solo (cierra y abre con fundido a blanco). Regenerar: `ffmpeg -i squarenet-full-loop-v2.mp4 -an -vf scale=1280:800:flags=lanczos -r 60 -c:v libx264 -preset slower -crf 28 -pix_fmt yuv420p -profile:v high -g 120 -movflags +faststart media/squarenet-loop.mp4` (y `scale=960:600`, `-r 30`, `-g 60` para el `-sm`). ffmpeg no está en el PATH: `npm i ffmpeg-static` en una carpeta temporal fuera del repo.
  - **Comportamiento** (JS inline al final de `index.html`): el video se carga cuando el laptop está a <900 px del viewport, corre solo mientras se ve (pausa al salir de pantalla o con la pestaña oculta) y hay un botón pausa/play (WCAG 2.2.2). Con `prefers-reduced-motion` o `Save-Data` no autoreproduce ni descarga nada hasta que el usuario pulsa play (queda el póster). El póster es un `<img>` encima del video que se desvanece al disparar `playing`.
- **`index.html` feature-carousel**: 8 slides (crossfade + zoom Ken Burns al cambiar, texto entra escalonado). Sin auto-advance (el usuario decide: dots, flechas, o swipe táctil en mobile — las flechas se ocultan en mobile porque colisionaban con el texto). Copy real y SEO-friendly (décimos, IESS, SRI, RDEP, etc.) — verificar contra `modulono.html` antes de agregar claims nuevos.
- **`index.html` `.feature-slide-art`**: un sketch SVG de línea blanca por slide (viewBox 240×240, marco de esquinas tipo viewfinder), dentro del `.wrap` como flex item con `justify-content:space-between` — así queda en el hueco entre el texto y la flecha en cualquier ancho (el `padding-right` extra del wrap es lo que evita que choque con la flecha, que está anclada al borde del viewport). Se ocultan a ≤860px.
  - **Sistema de animación**: los trazos con `data-draw` se dibujan solos — el JS mide `getTotalLength()`, setea `--len` y un `--d` escalonado, y recién ahí agrega `art-ready` al carrusel (sin esa clase no corre ninguna animación, así no parpadea antes de medir). `data-pop` = entrada con escala. Todas las animaciones están gateadas en `.is-active` para que solo anime el slide visible. Fallback: si el JS no corre, los sketches se ven estáticos y completos.
  - **Escenas, no íconos**: cada slide es una mini-historia en loop, al nivel de la de Auditoría (la favorita del cliente: documento + lupa de vidrio que recorre las filas, el `fx` adentro, tarjeta con la fórmula). Las otras 7: Plataforma (ficha del colaborador al centro; Asistencia/Acceso/RRHH/Nómina le mandan paquetes y se encienden sus filas), Ley (archivos IESS / RDEP / SRI 107 que se generan + sello "al día"), Soporte (rol de pagos con una fila en error magenta; cursor real con etiqueta "Soporte" la corrige, toast "Corregido"), Biométricos (reloj que escanea la huella, marca 08:02 y la marcación viaja a la tabla de asistencia), Configuración (editor `fx [0100] / 30 * [0180]` —la fórmula real de Sueldo devengado— que se escribe token por token y calcula la vista previa), Automatización (engranaje que dispara notificaciones a un celular) y Escalabilidad (matriz + sucursales que se conectan, contador 1→7).
  - **Cómo están armadas**: clases con prefijo por slide (`s1-…` a `s8-…`; Auditoría usa `art-lens/art-card`). Todas comparten la misma línea de tiempo: `10s`, delay `2.8s` (después del dibujado), `infinite backwards`, con la coreografía en `%` dentro de cada `@keyframes`. Su CSS vive entre `/* art-scenes:start */` y `/* art-scenes:end */` (se generó con un script, ahora se edita a mano). Regla clave: el **estado base de cada elemento es el estado final** de la historia (filas encendidas, sello puesto, valores calculados…), y los keyframes lo ocultan en las fases previas — así con `prefers-reduced-motion` (que apaga todas las animaciones) se ve la escena completa. `[data-fade]` = fundido de entrada (relleno de paneles, textos). El escalonado del dibujado es adaptativo (`gap = min(.075, 1.6 / nº de trazos)`) para que termine a tiempo aunque haya muchos trazos. Los textos dentro del SVG usan `.art-t` (+ `.art-mono` / `.art-cap`); nunca menos de ~5.6px (se ven a ~1.4×).
  - Acento cian (`--color-accent-300`) + `drop-shadow` en los elementos focales; magenta solo para el "error" de Soporte.

## Reveal on scroll compartido

`js/reveal.js` + la regla `[data-reveal]` en `broadsheet.css`: cualquier elemento con `data-reveal` entra al hacerse visible, y los hermanos directos se escalonan solos vía `--rd`. Lo usan plataforma, modulos, lectores y blog (somos tiene su propio sistema guiado por scroll). Si no hay IntersectionObserver o el usuario pidió `prefers-reduced-motion`, marca todo como visible de una. **Ojo**: igual que el `.reveal` viejo de `index.html`, depende de JS — sin JS el contenido queda en opacity 0.

## Cómo probar cambios visuales

No hay entorno de test automatizado. Para verificar cambios de UI:
1. Servidor local: `python -m http.server 8891` desde la raíz del repo. **Excepción**: si la página tiene `<video>` hace falta un servidor con soporte de `Range` (el de Python no lo tiene y el video no hace seek/empalma bien); basta un `http.createServer` de Node de ~30 líneas que responda 206 a los pedidos con `Range`.
2. Screenshot real vía Chrome headless + CDP (más confiable que el flag `--screenshot` de un solo uso):
   - Lanzar `chrome.exe --headless=new --remote-debugging-port=9444 --user-data-dir=<carpeta temporal propia>` — **siempre pasar `--user-data-dir` propio**, si no se engancha al perfil de Chrome real del usuario.
   - Para mobile real (no solo una ventana angosta): usar `Emulation.setDeviceMetricsOverride` con `mobile:true` vía CDP. Un `--window-size=390,...` sin esto se queda clampeado a un mínimo de ~500px por Chrome y las capturas salen recortadas/engañosas.
   - **No usar `--virtual-time-budget`** para nada que dependa de `requestAnimationFrame` (contadores animados, etc.) — no lo hace avanzar de forma confiable y los valores capturados quedan a medio animar. Usar espera de reloj real en su lugar.
   - Para animaciones por CSS (loops coreografiados, covers): congelarlas en un instante exacto con `document.getAnimations().forEach(a => { a.pause(); a.currentTime = T })` y capturar — así se revisa cada fase sin depender del reloj.
   - Para páginas guiadas por scroll (somos): capturar varios cuadros del viewport haciendo `scrollTo` y esperando ~1 s entre cada uno (los efectos dependen del evento scroll). Una captura "full page" no sirve porque no dispara los observers.
   - Matar los procesos de Chrome/servidor de prueba al terminar (buscar el PID por el puerto con PowerShell `Get-NetTCPConnection`, no asumir que el proceso hijo de bash lo mata solo).
   - Windows/CRLF: el repo trabaja en CRLF (`core.autocrlf=true`). Si se generan archivos con scripts, escribir con `\r\n`; verificar que no queden LF sueltos.
